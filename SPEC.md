# KartLog — Technical specification (v0.6, aligned with app 1.1.2 plus phase C1)

Offline Android tracker for the Mario Kart World collectibles: outfits (skins), Peach Medallions, P Switches, with a "Consigliami" module that suggests which Grand Prix or Knockout Tour to race, and with which character, to unlock more missing outfits.

> Working name: "KartLog". Do not use "Mario", "Mario Kart" or "Nintendo" in the app name, icon or package.
> The UI strings quoted below ("Consigliami", "Non ora", …) are the app's Italian texts (default language); the English ones are in `values-en/`.

---

## 0. Rules for whoever implements (read first)

1. **Never invent game data.** Characters, outfits, foods, cups, rallies, courses, medallions and P Switches come **only** from the seed JSON files (§5), generated by `tools/seedgen`. Do not edit `seed/` by hand. If a piece of data is missing, stop and ask the author: do not use plausible values in its place.
2. **No Nintendo assets in the repository**: no renders, logos, fonts or screenshots, neither in the repository nor in the APK. The images of characters, outfits and events are downloaded **at runtime** from the Super Mario Wiki CDN (`imageUrl` URLs in the seed, extracted by seedgen from the "Mario Kart World" page); until they are there a placeholder with the initials is shown. Author's decision of 26/09/2026, see `docs/decisions.md`.
3. **Offline except images and updates**: the INTERNET permission is only for downloading the images of point 2 and for checking/downloading this repository's releases on GitHub (`api.github.com`, §4.1; switched off with the "Mai" frequency); no analytics, no other traffic, and the app works entirely without a network too. Game data is downloaded **only at build time**, in the data extraction script (§5).
4. Work in phases (`docs/roadmap.md`). At the end of each phase the project must compile and the tests must pass. Non-obvious choices and their reasons are in `docs/decisions.md`.

## 2. Navigation and UI

### 2.1 Structure
- `ModalNavigationDrawer` with a hamburger at the top left, always available.
- Drawer entries: **Home**, **Personaggi** with the sub-item **Cibi** (§2.3.1, indented and smaller like those of Collezionabili), the **Collezionabili** section (non-clickable header with three smaller, indented, always visible entries: **Monete Peach**, **Pulsanti P**, **Pannelli ?**), **Mappa del mondo** (§2.4), **Consigliami**, **Risultati**, and further down **Impostazioni / Info** (credits and data licenses, §5.5).

### 2.2 Home
- 2×2 grid of large buttons (the author's layout, 28/09/2026): **Personaggi, Risultati** / **Pulsanti P, Mappa del mondo** (§2.4). Monete Peach no longer has a tile: it stays in the side menu and on the map.
- Each button shows an icon, a title and a progress counter (e.g. `87 / 127`); for Risultati (§2.6) it is the number of trophies recorded, one per event + engine class pair of any level, out of events × 4 engine classes (`12 / 80`). The World map has no counter; its icon is drawn (white map on a red disc).
- Below the grid, a full-width button **Consigliami** (§2.5) with a line of explanation ("Quale Gran Premio o Knockout Tour correre, e con chi, per sbloccare più outfit") and no counter.
- The look must be colourful and "game-like": vivid palette, generous rounded corners, bold typography. It must not imitate the official UI. Since 26/09/2026 it follows the author's mockup: banner with sky and track (logo on Home, title elsewhere) at the top of every screen, gradient tiles with faint checks, round icon, white title with dark outline and counter in a pill, track at the bottom of Home. Title font Lilita One.

### 2.3 Personaggi
**Character list screen** (it was called "Skin")
- Adaptive `LazyVerticalGrid` (**3 columns** on phone): the images are vertical, in the proportions of the game's selection screen. There are **all 50 drivers**: the 24 with alternative outfits and the 26 that have only one (Goomba, Cow…).
- Each cell shows the character's image (placeholder with initials until downloaded), the name and an `obtained/total` counter; for drivers without outfits, "Sbloccato" / "Da sbloccare". A padlock on the image marks those not yet unlocked.
- Tap: locked driver → popup with the unlock criterion (mariowiki) and the switch; unlocked with outfits → detail; unlockable without outfits → the popup again (to be able to lock it again); starter without outfits → nothing.
- Initial unlock state from the wiki: the 32 "starter" drivers start unlocked, the 18 "unlockable" ones (DK, Daisy, Rosalinda, Lakitu, Bowser Jr., Strutzi, Re Boo included) do not. Consigliami considers only unlocked characters (§6).
- The detail shows the outfits as a grid of cards with their image (2 per row on phone); the default outfit uses the character's image.
- If the character has **all** the outfits (for drivers to unlock without outfits: if unlocked) it is sorted to the bottom; starter drivers without outfits have nothing to complete and are sorted together with the others (the "Incompleti" filter does not show them). Colours (the author's rule, 27/09/2026): **grey = you are missing it, coloured = you have it**, so the cell is grey only if the driver is to be unlocked (with padlock and criterion popup); in the detail the outfits not yet obtained are grey. Starter drivers are always unlocked. The ordering is configurable: roster / alphabetical / % completion. "Roster" is the order of seedgen's `aliases.yaml` (first the 24 with outfits, then the others), **not** that of the game's selection screen: the author's choice, who prefers it.
- Filter at the top: Tutti / Incompleti.

**Character detail screen**
- Header with name, counter and, for drivers to unlock, the unlock criterion and the switch **"Personaggio sbloccato"**, needed for Consigliami (§6). Starter drivers are always unlocked and have no switch.
- Outfit list: each row has a checkbox, the outfit name and **all** the food groups that unlock it (e.g. Mario Touring: "Hamburger · Barbecue · Moo Moo Milk"). If there are no known rules, it shows "cibo sconosciuto". Each food group is a tappable underlined text that opens `Destination.FoodDetail` (§2.3.1); tapping it does not tick the outfit, the rest of the polaroid does.
- The default outfit is not a tickable row: it is always owned and does not count among the missing ones.

### 2.3.1 Cibi (phase C2)
Sub-section of Personaggi, reachable from the drawer; it is not a collectible and has no user state. From the character detail (§2.3) every food under an outfit is tappable and opens `FoodDetail` (phase R1); "cibo sconosciuto" is not.

**Grid** (`ui/food/`, `Destination.Food`): one `KartPanel` tile per food group (20, in seed order), adaptive columns (min 150 dp), with the image of the first variant (placeholder with initials until loaded), the name in the app's language (unofficial translation) and a "Ne mancano N" pill with the outfits the food gives and that you do not have (`outfit_food_rules` without `owned_outfits`), or "Nessun outfit" (lunchbox). Foods are never greyed out.

**Detail** (`Destination.FoodDetail(foodGroupId)`): at the top the variants (image in a uniform box, because the wiki ones do or do not have a built-in frame; name, boost); "Dove si trova": one section per group, split by variant only for sushi (the source names the exact food), in panels "Sui percorsi" (biome › course and the places) and "Sulle strade" (biome if the source says it, then the place); "Outfit che sblocca": one panel per character, two per row (a food gives at most one outfit per character, checked on the seed), first the characters who are missing the outfit and then the others, in roster order within the same group, with avatar and small polaroid of the outfit, **grey if you do not have them, coloured if you do** (not tickable from here); at the bottom the characters with outfits to whom this food gives none. The stands on the courses are in the area, not necessarily on the track (§6.1). Pure grouping logic in `FoodDetailModel.kt`.

### 2.4 Peach Medallions and P Switches
At the top is the global counter (`x/200`, `x/394`). At the bottom right, overlaid, a big round **red button with the white map icon** opens the Map with only the points of that screen; each row also has a "Mostra sulla mappa" icon that opens it centred on that point.

**Peach Medallions** (since 28/09/2026, mkworld-checklist data, §5.2)
- The **200 coins one by one**, in order, each with a checkbox and the instructions to find it (English only). No more biomes: the source does not give them.
- The per-biome counts of the previous version cannot be converted (they do not say which coins): the Room v6→v7 migration deletes them and the app shows once a notice with how many coins had been ticked (author's choice).

**P Switches**
- Collapsible sections by region; within each region, sub-groups by course (or place, e.g. Chain Chomp Desert).
- Each row shows the mission name (in-game text from the wiki) and the course. Mission names stay in English: the Italian list of mariowiki.it is incomplete and has no key to match it with the English one (see `tools/seedgen/seedgen/it_wiki.py`).
- Text search on the mission name.
- The **10 regions** (`regions.json`, Italian names from mariowiki.it) each have `x/y` and a "segna tutti" action that asks for confirmation.

**Map** (drawer entry, and the big button of the two screens above)
- The world map image from mkworld-checklist, downloaded at runtime like the wiki images (URL in `map.json`, never in the APK); without network and without cache only the sea remains, and the points can still be seen and tapped.
- Zoom with pinch or double tap (up to ×8), drag; the markers grow with zoom (small with the whole map, full from ×4) but do not follow the image's magnification. Shape and symbol per type: P Switch = blue circle with "P", Peach Medallion = pink coin with crown, "?" panel = yellow square with "?"; points already done remain recognizable, dimmed, with a green tick.
- **Visual filters** at the top (red big buttons in a 2×2 grid): one toggle per type, with the marker as legend and the `done/total` counter, and "Mostra fatti" to show or hide the points already done. Opened from a screen, it shows only its type.
- Tap on a point: popup (§ graphics) with the mission name and place (P Switches), the instructions (English), the "Presa/Completata/Attivato" switch and "Guarda il video" (YouTube, `ACTION_VIEW` Intent). The state is the same as the lists.
- The **"?" panels** (150) also have a one-by-one list like the Peach Medallions (same shared screen, `MapPointListScreen`), with no counter on Home.

### 2.5 Consigliami
See §6 for the algorithm. UI:
- Mockup graphics (phase C3): at the top a blue tile with the big buttons **Gran Premi** / **Knockout Tour** / **Entrambi**, the "Pesa i risultati" switch (`KartSwitchRow`) and, with results on, weight slider and reference engine class; the warning about the stands ("occhi aperti", outfit change can be switched off) sits behind an "i" (`KartInfoButton` + `KartPopup`). The cards are `KartPanel`s: orange for Grand Prix, green for Knockout Tour.
- Toggle: **Gran Premi** / **Knockout Tour** / **Entrambi**.
- List sorted as per §6.4, one card per event numbered 1, 2, 3… Only the events where at least one unlocked character could obtain an outfit: the others never appear (no "Solo utili" filter, removed on 05/10/2026).
- Each event card shows:
  - event name, type (Cup/Rally) and ranking position
  - **recommended character** and the number of new outfits they could obtain ("fino a +N")
  - the next 2 alternative characters with their respective numbers
  - the relevant foods that **might be there** in the event, each with the course: the Yoshi's stand is in the course's area, not necessarily on the race track ("occhi aperti", §5.2.1)
  - if results are on, the trophy recorded at the reference engine class (§2.6)
- Tap on the card opens the detail (phase C4): a warning at the top, once only (outfits that *might* unlock); one tile for each character with gain > 0, in the character's colour, with avatar and "fino a +N outfit"; for each outfit a row "Vespone – [Barbecue · Spiaggia di Peach]" in which the food is a button (image, name, event courses with a stand selling it, several courses in the same button) that opens that food in the Cibi section (§2.3.1); at the bottom a tile with the best trophy for each engine class **read-only**. Consigliami does not record results: this is done only from the Risultati screen (§2.6).
- "Pesa i risultati" section: on/off switch plus weight slider (§6.3).
- Warning behind the "i" of the controls tile: the indicated stands are in the courses' area, not necessarily on the track ("occhi aperti"); if the snack outfit change is switched off in the vehicle selection, nothing is unlocked (Dash Food page).
- Event icons and character avatars with a dark outline, in the list and in the detail.
- The "Includi cibi nei dintorni" switch is gone (removed with phase C1: the Cibi section of phase C2 shows all the places).

### 2.6 Risultati
Dedicated screen, reached from the wide button on Home and from the drawer. It records the **best result** of every Grand Prix and Knockout Tour, not a history.
- The result is a **trophy** on a single ascending scale: bronze, silver, gold, gold ★, gold ★★, gold ★★★. Stars exist only with gold; from 4th place down there is no trophy, so it equals "no result". Sources: [Game Rant](https://gamerant.com/mario-kart-world-grand-prix-how-get-three-stars-rank-gold-trophy/) (scale), [TheGamer](https://www.thegamer.com/mario-kart-world-grand-prix-knockout-tour-three-star-guide-how-to/) (Knockout Tour: 1st gold, 2nd silver, 3rd bronze, from 4th no trophy).
- One trophy per (event, engine class) pair: choosing another **replaces** the previous one, and "Nessun trofeo" deletes it.
- Engine class selector (50/100/150/Mirror, default 150cc) and a list of all events, split into Grand Prix and Knockout Tour, never filtered by Consigliami. Graphics (phase R1): section headers `OutlinedTitle`, each event a `KartPanel` (orange GP, green KO) with `EventIcon(outlined = true)`, name and trophy pill (grey = none, yellow = recorded); tapping opens a `KartPopup` with one `KartChoiceButton` per trophy plus "Nessun trofeo".
- A trophy counts **only** for the engine class in which it is recorded: no automatic carry-over to lower engine classes, because the game's behaviour is not confirmed with certainty (author's decision).

## 3. Data model (Room)

Seed data (read-only, reloaded at every `seedVersion` change):

The entities follow the JSON files of `seed/` (§5.1), which already exist in the repository.

```
Character(id: String PK, name: String, nameIt: String?, rosterOrder: Int, starter: Boolean,
          unlockCriteria: String?, unlockCriteriaIt: String?, imageUrl: String?)   // 50 drivers; there is also imageRes, a leftover of the scaffold, always null
Outfit(id: String PK, characterId: FK, name: String?, nameIt: String?, isDefault: Boolean, imageUrl: String?)
    // id = "<character>__<outfit>": names are NOT unique across characters ("Pro Racer").
    // The default has id "<character>__default" and name null (the wiki does not name it): in the UI "Standard".
FoodGroup(id: String PK, name: String, nameIt: String?, foods: List<String>, revertsToDefault: Boolean)   // nameIt: unofficial translation
    // One group = one distinct Outfits cell of the Dash Food table (20 groups).
    // foods: names of the foods that compose it, e.g. ["Takoyaki","Candy apple","Cheep Cheep taiyaki","Sushi"].
OutfitFoodRule(outfitId: FK, foodGroupId: FK)              // N:M: the same outfit is obtained from several groups (e.g. Mario Touring)
FoodVariant(id: String PK, foodGroupId: FK, order: Int, name: String, nameIt: String?, boost: List<SMALL|MEDIUM|LARGE>, imageUrl: String?)
    // A row of the Dash Food "List of food" table (60): usually 3 per group; sushi has 4 foods
    // (takoyaki, candy apple, taiyaki, sushi), the triple plate has boost [SMALL, MEDIUM, LARGE].
    // id "<group>_<n>"; nameIt: UNOFFICIAL translation.
YoshiStand(id: String PK, order: Int, courseId: FK?, regionId: FK?, establishment: String?, establishmentIt: String?,
           location: String?, locationIt: String?)
    // A stand of "List of Yoshi's locations" (one row = one photo = one stand): 70 in the area of 21 courses,
    // 39 on the roads (courseId null). regionId = the course's; null on the roads (the source does not say).
    // location null = the wiki does not indicate it. *It: UNOFFICIAL translation. id "stand_<course>_<nn>" / "stand_route_<nn>".
YoshiStandFood(standId: FK, foodGroupId: FK, food: String?)    // PK (standId, foodGroupId)
    // food = exact food only where the source names it (sushi group, = FoodVariant.name); null = the whole group.
Course(id: String PK, name: String, nameIt: String?, regionId: FK?)   // regionId null only for Rainbow Road
Region(id: String PK, name: String, nameIt: String?, order: Int)     // 10 regions/biomes
Area(id: String PK, name: String, regionId: FK)               // places of the missions that are not one of the 30 courses
PeachMedallion(id: String PK, index: Int, x: Double, y: Double, hint: String?, youtubeId: String?)   // 200, mkworld-checklist (§5.2)
QuestionPanel(id: String PK, index: Int, x: Double, y: Double, hint: String?, youtubeId: String?)    // 150, mkworld-checklist
PSwitch(id: String PK, index: Int, regionId: FK, courseId: FK?, areaId: FK?, name: String, x, y, hint, youtubeId)  // 394, exactly one of courseId and areaId
    // x, y: percentage of the map image (map.json: imageUrl, width, height, read from the assets, no table)
Event(id: String PK, type: CUP|RALLY, name: String, nameIt: String?, order: Int, imageUrl: String?)
EventStop(eventId: FK, position: Int, courseId: FK)         // in the JSON it is the event's "stops" array, in order
```

The mirror mode conditions (`mirror_mode.json`) and the map image (`map.json`) are read from the assets, with no table. Room v8: `food_group_courses` (up to v7) is replaced by the stands (`MIGRATION_7_8`).

User state (the reseed does not delete it; it only remaps the old P Switch IDs, phase P1):

```
OwnedOutfit(outfitId PK)
CharacterUnlock(characterId PK, unlocked: Boolean)
CollectedMedallion(medallionId PK)
CompletedPSwitch(pSwitchId PK)
ActivatedQuestionPanel(panelId PK)
PendingNotice(id PK, count: Int)        // notices to show once, written by a migration (v6 -> v7)
BestResult(eventId, cc, rank: BRONZE|SILVER|GOLD|GOLD_1_STAR|GOLD_2_STARS|GOLD_3_STARS)   // PK (eventId, cc), §2.6
    // Schema v3. Up to v2 it was RaceResult (history with stars and position independent): the migration
    // keeps the highest level per (event, engine class) with 1st -> gold + stars, 2nd -> silver, 3rd -> bronze.
```

The reseed uses upserts on the static data and does **not** delete user state; before recording the new `seedVersion` it moves onto the new IDs the P Switches saved with positional IDs (`p_switch_legacy_ids.json`, §5.1). Seed IDs are stable strings (slugs), never autoincrement nor position in the page.

## 4. Extra persistence
- JSON export/import of the **user state** (not of the seeds) through the Storage Access Framework, for manual backup.

### 4.1 In-app updates and the Info section (phase A1)
- **Check**: only at startup (once per process) and never in debug builds (signed with the debug key, a release cannot be installed over it); "Controlla aggiornamenti" in Info always does it, even with "Mai". Source: `GET https://api.github.com/repos/Marcogn/KartLog/releases/latest`, without token (limit 60 requests/hour per IP). Frequency (Settings, `KartDropdown`): Mai / A ogni avvio / Ogni giorno / Ogni settimana, **default every week**; `UpdatePreferences` (SharedPreferences `update_prefs`, like the pilot) holds frequency and `lastCheckAt`, written only if GitHub answered.
- **Dialog** (`UpdateDialogHost` above the graph, driven by `UpdateManager.state`; `KartPopup`): new and installed version, release titles (the CHANGELOG bold titles, `release.yml`), "Changelog completo" (opens GitHub), **Scarica** / **Non ora** ("Non ora" just closes); progress with **Annulla**; explicit **Installa** once download and verification are done; errors with the reason.
- **Checks before installation**: single `.apk` asset (there is also `KartLog-x.y.z-mapping.txt`), size and SHA-256 against the asset's `digest`, same package, higher `versionCode`, same signing certificate; then a `PackageInstaller` session with system confirmation (`REQUEST_INSTALL_PACKAGES`, "install unknown apps"). No silent installation, no pre-releases, no background checks.
- **Info** (bottom of Settings): name, `VERSION_NAME` (not the version code), "Controlla aggiornamenti" with the result, the note that the app connects to GitHub only for this, "Fatto con il ❤️ da Marcogn" / "Made with ❤️ from Marcogn", link to the repository, MIT license, then the attributions of §5.5.

### 5.2 Sources
All from **Super Mario Wiki** (mariowiki.com), text content under CC BY-SA 4.0. Pages are pinned by **exact title** in `tools/seedgen/sources.yaml`: the script does not search for pages, and if a title changes the extraction fails.

| Page title | What is extracted |
|---|---|
| `Dash Food` | "List of food" table: food groups → outfit per character; each food (row) with boost level and image; Locations column (courses **and nearby roads**) only as a cross-check |
| `List of Yoshi's locations` | all the stands: "Course locations" (in a course's area: venue, food, place) and "Route locations" (on the roads: food, place) |
| `List of Mario Kart World missions` | P switches: biome (header), mission name ("In-game text"), course ("Location") |
| `Template:Mario Kart World` | the game's navbox: rows "<Name> Cup" with the 4 courses; row "Knockout Tour rallies" (to notice new rallies) |
| `Golden Rally`, `Ice Rally`, `Moon Rally`, `Spiny Rally`, `Cherry Rally`, `Acorn Rally`, `Cloud Rally`, `Heart Rally`, `Drill Rally`, `Boomerang Rally (rally)`, `Propeller Rally`, `Turnip Rally` | rally stages, from the "Starting point / Checkpoint N / Final course" table |

**Map, Peach Medallions and "?" panels: mkworld-checklist.** Since 28/09/2026, by the author's choice, the map positions of Peach Medallions, P Switches and "?" panels, the instructions (English only), the videos and the map image come from the public GitHub project [mkworld-checklist](https://github.com/BamisWasTaken/mkworld-checklist) (mktools.io), read by `seedgen/checklist.py` at a **pinned commit** in `sources.yaml`, with credits in the README, `seed/LICENSE` and Settings/Info. The coins and panels come only from there; the P Switches remain those of mariowiki and take their position by mission name (3 different spellings in `manual/checklist_mission_names.yaml`, an unmatched name stops the extraction). This supersedes the previous medallion source (per-biome counts from Nintendo Life, manual file): the mkworld-checklist coins have no biome, and an attempt to derive it from nearby P Switches did not reproduce Nintendo Life's counts. No automatic scraping of commercial sites (IGN, Game8, Nintendo Life): protected content, restrictive terms of use and unstable structure.

- Commercial guides (IGN, Game8, Nintendo Life, Gamer Guides) serve **only to verify** the data, not to copy their content. IGN is the author's reference for spot-checking outfits (manual, not automated).
- mariowiki's images are **not** CC BY-SA: they are Nintendo assets. seedgen records only the URL (`imageUrl` on characters, outfits, events from the `Mario Kart World` page, always live like the Italian-name pages; on foods from the `Dash Food` page); the app downloads them at runtime and they never enter the repository or the APK.

### 5.2.1 Domain rules verified on the Dash Food page
- **All foods of the same group give the same outfit**: snacks are not combinations. The wiki speaks of 18 official groups; for the app the distinct Outfits cell counts, which gives **20 groups** (19 with outfits + Lunchbox).
- Takoyaki, candy apple and Cheep Cheep taiyaki share sushi's Outfits cell: they are a single group.
- Snacks 1, 2 and 3 have different outfits but the same Locations column: a snack kiosk can give any of the three.
- The **lunchbox** gives no outfit: it reverts to the default (`revertsToDefault = true`, no rule).
- A character **not listed** for a group receives no outfit from that group.
- Baby Peach, Baby Daisy and Baby Rosalina always receive the same outfits among themselves; so do Toad and Toadette (Burger Bud ≡ Soft Server, Engineer ≡ Conductor). No special logic is needed in the app: it is a coherence check of the script.
- Only the 24 characters of the main roster have outfits; NPCs do not.

**Where a food is found: the Yoshi's stands** (phase C1, checks of 05/10/2026).
- The Locations column of Dash Food lists the courses *plus nearby roads* ("courses or surrounding routes"): it is not enough to say where a stand is.
- `List of Yoshi's locations` lists every stand: "Course locations" gives those **in the area** of a course, even outside the race track (Crown City has nine, some "in an alley next to Bank Coin Coffer"), and no source says which ones are met in a race; "Route locations" gives those on the roads between courses. That is why Consigliami speaks of possibilities and the stands on roads are never associated with an event (linking them to a rally stretch would mean guessing from a textual description).
- Cross-check: every food of a stand on a course also appears in the Locations column of Dash Food for that course (it holds for all pairs), otherwise seedgen stops.
- The food labels of the Yoshi's page ("Kebabs", "Fish and chips", "Chips, soft drinks, chocolate bars"…) map to the groups with `yoshi_food_labels` in `aliases.yaml` (checked on the Dash Food image file names, e.g. MKWorld_Kebab_1 = Barbecue). A snack stand counts for Snacks 1, 2 and 3. The sushi group's labels name the exact food (takoyaki, candy apple, taiyaki, sushi) and the stand goes to that food; the others name the group, not the size.
- For 9 courses (Desert Hills, DK Pass, Faraway Oasis, Dino Dino Jungle, Dandelion Depths, Boo Cinema, Choco Mountain, Toad's Factory, Rainbow Road) the page lists no stands: for the app they count as "no known stand", not as "no food". Wild bone and popcorn have stands only on roads, so Consigliami never suggests them.
- From the vehicle selection the outfit change from Dash Food can be **switched off**: in that case no outfit is unlocked (Dash Food page). The Consigliami banner says so.

### 5.3 Extraction script (`tools/seedgen/`, already in the repository)
The script **already exists** and is covered by tests: it must not be rewritten, only extended when new sources are needed. Usage details in `tools/seedgen/README.md`.

**Pipeline:** download (MediaWiki API) → parse → raw data → normalization with `aliases.yaml` → validation with `expected_counts.yaml` → deterministic JSON.

**Data access**
- `https://www.mariowiki.com/api.php?action=parse&page=<title>&prop=text|revid&formatversion=2`. The HTML returned by the API is used because the Dash Food table has rowspan/colspan and image links that are awkward to interpret in wikitext; in HTML they become normal cells and `<a title="Course">`.
- Sequential requests, `User-Agent` with contact (to be set in `sources.yaml`, replacing `<REPO_URL>`), `maxlag=5`, retry with backoff on 5xx/429/maxlag, per-request and total timeout.

**Parsing**
- Each table is looked up by **headers** (e.g. Name/Outfits/Locations), never by position. Unexpected structure = error.
- Character and course names normalized through `aliases.yaml`. An unknown name makes the extraction **fail**. Links to ignore (e.g. "Mario Circuit 1/2/3" in the Special Cup) are listed explicitly.
- If the navbox lists a rally not present in `sources.yaml`, the extraction fails: new rallies are added knowingly.

**Validation (exit code 2 if one fails)**
- Counts in `expected_counts.yaml`: 24 characters with outfits, 103 alternative outfits, 127 total, 20 food groups (1 that reverts to the default), 60 foods, 70 stands on courses and 39 on roads, 30 courses, 8 cups of 4 courses, 12 rallies of 6 stages. If a game update changes the numbers, they are updated **by hand** in a dedicated commit, never relaxed to make the build pass.
- Referential integrity, unique IDs, no outfit without food, every group with at least one stand and one variant, the 8 cups cover all 30 courses.
- Equivalences of §5.2.1 and cross-check course stands ⊆ Dash Food Locations column (in the build).
- Stands: biome equal to the course's, no biome on roads, every place and venue type with its translation (`manual/stand_locations_it.yaml`: a text without an entry or an unused entry stops seedgen). Foods: recognized boost level, image on the wiki CDN (original file).
- 10 regions; every course except Rainbow Road in exactly one region.
- Map (if present, all or none among `peach_medallions.json`, `question_panels.json`, `map.json`): 200 coins, 150 panels, unique IDs, every point with `x`/`y` between 0 and 100, image only on `raw.githubusercontent.com/BamisWasTaken/mkworld-checklist/`.
- P Switches (if present): exactly 394, and every mission is in the region of its own course. This check also verifies the course→region assignment in `aliases.yaml`, which for 7 regions out of 10 is derived from the Nintendo Life guide.

**Commands and exit codes**

| Command | Use |
|---|---|
| `validate --seed DIR` | validates an existing seed, without network |
| `fetch-fixtures` | saves the real pages in `tests/fixtures/real/` |
| `generate --out DIR [--from-fixtures DIR \| --from-raw FILE]` | generates and validates |
| `check --seed DIR --candidate DIR` | compares, prints the diff |
| `accept --seed DIR --candidate DIR` | copies the candidate, increments `seedVersion`, prints the line for the CHANGELOG |

Exit codes: `0` ok/identical · `1` usage or configuration · `2` invalid data · `3` valid but different from `seed/` · `4` network.

**Status**
- Parser tested on synthetic HTML and on the real pages (`tests/fixtures/real/`, committed; `test_real_fixtures.py`). The pages with names in other languages and the images page are always read live (live tests skipped without network).
- `seed/` extracted via API (`origin: api`), `seedVersion` 9.

### 5.4 Integration in the Gradle build
The script runs during the build, with different rules per variant:

| Variant | Behaviour |
|---|---|
| **debug** | No network, no Python. Uses the versioned JSON in `seed/`. |
| **release** | Task `generateSeed` before `mergeReleaseAssets`: runs `python -m seedgen release --seed <root>/seed --work app/build/seedgen/candidate`. |

Behaviour by `release` exit code:
- **0**: data identical to `seed/`, the build continues.
- **3**: valid but different data. The build **stops** showing the diff printed by the script. With `-PacceptSeedChanges` the task runs `accept`, inserts into the CHANGELOG the line printed by `accept` (in the project's CHANGELOG format) and continues. This way every release is reproducible from the commit and no data change enters unseen.
- **2**: invalid data, the build **fails**. Unvalidated data is never used.
- **4** (network) or **1** (configuration): the build **fails**. With `-PofflineSeed` the task passes `--offline`: it validates the versioned `seed/`, writes a warning and continues.

Requirements:
- The task finds `python3` from the PATH or from `-PpythonExec`; if missing, a clear error with instructions.
- Dependencies installed from `tools/seedgen/requirements.txt` in a venv under `build/` (not in the system).
- The network part is never cacheable (`outputs.upToDateWhen { false }` or equivalent).
- The task copies `seed/*.json` into the assets (e.g. generated, unversioned `app/src/main/assets/seed/`) in both debug and release.
- Document in the README: Python prerequisites, available flags, how to update `expected_counts.yaml` and `sources.yaml`.

## 6. Consigliami algorithm

### 6.1 Foods that might be in an event
```
foods(E) = { f.foodGroupId | f ∈ YoshiStandFood, stand(f).courseId ∈ courses of EventStop(E) }
```
`foods(E)` is a set of food **groups**, taken from the Yoshi's stands in the area of the courses touched (phase C1). The stand may not be on the race track, so every gain is a **possibility** and the texts say so ("potrebbe esserci", "occhi aperti"). The stands on roads (`courseId` null) never enter `foods(E)`.

### 6.2 Gain per character
For each **unlocked** character C and each event E:
```
missing(C) = outfits of C that are not default and not owned
gain(E, C) = | { o ∈ missing(C) : ∃ rule(o, f) with f ∈ foods(E) } |
best(E)    = argmax_C gain(E, C)   // tie-break: C with more total missing outfits, then rosterOrder
total(E)   = Σ_C gain(E, C)
```
An outfit with no known food rules enters no gain and appears as "cibo sconosciuto" in the detail.

### 6.3 Score
The primary criterion is **always** the gain of the best single character, because in a run only one is used. It is not configurable.

- **Results off:** `score(E) = gain(E, best(E))`.
- **Results on** (weight `w ∈ [0, 1]`, default 0.3):
  ```
  normGain(E)    = gain(E, best(E)) / max_E gain(E, best(E))    // 0 if max = 0
  improvement(E) = 1 - level(bestRank(E, selectedCc)) / 6       // bronze=1 … gold ★★★=6; no trophy → 1
  // bestRank(E, cc) = trophy recorded exactly at cc (§2.6), no carry-over from other engine classes
  score(E)       = (1 - w) * normGain(E) + w * improvement(E)
  ```
  The reference engine class is selected in Consigliami (default 150cc).
- Events with `gain(E, best(E)) = 0` excluded from the list, even with results on (where `w * improvement` would give them a positive score).

### 6.4 Ordering and position
Supporting metrics:
```
relevantStops(E) = | { s ∈ EventStop(E) : ∃ f ∈ foods(course of s) (§6.1) that unlocks an outfit in missing(best(E)) } |
worstFirst(E)    = improvement(E)            // only if results are on
typeRank(E)      = 0 if CUP, 1 if RALLY      // a GP races a full lap on the course; a rally often crosses it only partly
```

**Position:** the index in the sorted list + 1 (1, 2, 3…). No shared number for ties: until 05/10/2026 it was "competition ranking" (1, 1, 3) with ties in an expandable card, but on screen it looked as if the ranking skipped places (author's decision).

**Full ordering** (descending where not indicated):
1. `score(E)`
2. `total(E)`
3. `relevantStops(E)`
4. `worstFirst(E)` (skipped if results are off)
5. `typeRank(E)` ascending (Cup before Rally)
6. `Event.order` ascending

Criteria 3–6 decide the order between events with the same score and the same total.

### 6.5 Required tests
- No missing outfit: the list is empty.
- An event without possible outfits stays out even with results on.
- A locked character is never recommended.
- An owned outfit does not count.
- A food present in two courses of the same event counts only once per outfit.
- With `w = 1`, the ordering depends only on `improvement`.
- Deterministic tie-break.
- Three events with the same score and total all stay in the list, one after the other.
- With everything equal, a Cup precedes a Rally.
- An event with more useful courses (higher `relevantStops`) precedes one with fewer, with the same score and total.
- The event with more outfits comes first; progressive positions even with equal gain.
- A stand on a road gives no gain to any event (neither relevant foods nor detail).
- Several stands with the same food on the same course count once.
- The detail gives, for each outfit, the foods and the event's courses from which it might come, in stage order.
