# Project decisions

KartLog's non-obvious choices and the reasons for them, grouped by topic. It summarizes the old chronological log in `CLAUDE.md` (up to 05/10/2026), leaving out decisions superseded by later ones: those remain in git history.
A new decision goes in the right section, with its date. A decision that supersedes another **replaces** it here (they do not pile up).

## Game data and sources

- **Main source: Super Mario Wiki** (mariowiki.com, CC BY-SA 4.0), pages pinned by title in `tools/seedgen/sources.yaml`. If a title changes, the extraction fails and is updated by hand (example: 03/10/2026, "Boomerang Rally (Mario Kart World)" → "Boomerang Rally (rally)", same rally, `seedVersion` 8). (25/09/2026)
- **Commercial guides** (IGN, Game8, Nintendo Life, Gamer Guides): only to check by hand, never automatic scraping nor copied content (protected, restrictive terms, unstable structure). IGN is the author's reference for spot-checking outfits. (25/09/2026)
- **mariowiki.it** (CC BY-SA 4.0) as a second source, only for the Italian names that mariowiki.com does not have. Matches are always verifiable, never by position: drivers via langlink (or `itWikiPage` in `aliases.yaml`), Trophies/rallies by sequence of stages, biomes by the courses cited in the section intro. P switch missions are not localized: the Italian list has ~30 translations out of 394 and only 6 match with certainty. (26/09/2026)
- **mkworld-checklist** (BamisWasTaken, mktools.io) for the positions of Peach Medallions, P switches and "?" panels, instructions (EN), videos and the map image, at a commit pinned in `sources.yaml`, with credits in the README, `seed/LICENSE` and Settings/Info. The repository has no LICENSE file: reported to the author, who decided to use it. (28/09/2026)
- **Counts** (`expected_counts.yaml`): 127 outfits (103 + 24 default), 20 food groups, 50 drivers of which 32 starters, 394 P switches, 200 Peach Medallions, 150 "?" panels ("? Panel" page). Update 1.8.0: no new outfits (confirmed by the author), only 2 rallies already present. On the Kotlin side the file is read with a few-line parser (only `key: integer`), with no YAML dependency. (25–28/09/2026)
- **P switches** from the "List of Mario Kart World missions" page, by region and course. Region of `toads_factory` corrected to `central_grassland` and area "Big Donut" to `volcanic`, checked on the real page. Matching with mkworld-checklist by name: 391 identical, 3 differing by one word in `manual/checklist_mission_names.yaml`. (25/09, 28/09/2026)
- **Peach Medallions** one by one from mkworld-checklist, with no biome: the source does not give it, and assigning it using nearby P switches did not reproduce Nintendo Life's counts. `MIGRATION_6_7` deletes the old per-biome counts and shows once how many medallions had been ticked (`pending_notices`). IDs `medallion_<index>`/`panel_<index>` (stable index of the source). (28/09/2026)
- **Food → outfit** from the "List of food" table of the Dash Food page (domain rules in SPEC §5.2.1). Spot-checked again on 05/10/2026 (phase C1: hamburger, milk, sushi, lunchbox, Toad/Toadette and baby equivalences): the rules match the page (revid 5455370).
- **Yoshi's stands** (phase C1, 05/10/2026) from "List of Yoshi's locations" (revid 5263331), sections "Course locations" and "Route locations": **one row = one stand** (each row has its own photo; 70 + 39). They replace `food_group_courses.json`/`FoodGroupCourse` (presence ON_COURSE/NEARBY): the Locations column of Dash Food stays only as a cross-check in the build. IDs by position in the page (`stand_<course>_<nn>`, `stand_route_<nn>`): no user state uses them, so they may change at every extraction. Empty place on the wiki = `null`. Biome: the course's; on roads `null`, never deduced from the description. The roadmap's diagnosis said "Crown City: ten" stands: the rows are nine (the tenth is the header).
- **Stand labels → groups** (`yoshi_food_labels`), checked on 05/10/2026 against the image file names of Dash Food (MKWorld_Kebab = Barbecue, MKWorld_Flatbread = Spicy curry, MKWorld_Baked_goods = Bread, MKWorld_Meat = Wild bone…). "Meat" (single stand, east entrance of Crown Bridge) is also consistent with Dash Food, which puts the Wild bone at Faraway Oasis: Crown Bridge connects Crown City and Faraway Oasis (Faraway Oasis page). "Popcorn" is the food's name on Dash Food. The sushi group is the only one where the label names the exact food (Takoyaki, Candy apples, Taiyaki, Sushi): there the stand goes to its variant, in the other groups it applies to the whole group.
- **Foods one by one** (`food_variants.json`, phase C1): each row of the "List of food" table = one variant, 60 as the page says ("There are 60 kinds of Dash Food"). Sushi has four foods, the last is the triple plate with boost "Small, Medium, and Large (respectively)", saved as `[SMALL, MEDIUM, LARGE]`. IDs `<group>_<n>` in table order.
- **Real seedgen fixtures** (`tests/fixtures/real/`, ~1.9 MB) committed: without them, `test_real_fixtures.py` would be skipped in CI. The pages with names in other languages are instead **not** fixtures (tens of MB for a few rows): they are downloaded live, tested with synthetic fixtures plus live tests skipped without network. `test_versioned_seed_matches_golden` excludes `p_switches.json` (the manual transcription never covered them) and, since phase P1, `p_switch_legacy_ids.json`. (25/09/2026)
- **Initial unlock state** from the "Default drivers" (`starter`) and "Unlockable drivers" galleries of the "Mario Kart World" page. Effect accepted by the author: DK, Daisy, Rosalinda, Lakitu, Bowser Jr., Strutzi and Re Boo start locked and Consigliami ignores them until the user ticks them. (26/09/2026)
- **Unlock criteria** from the "Unlock criteria" tables (mariowiki.com) and "Criteri di sblocco" (mariowiki.it), matched by the driver's Italian name. (27/09/2026)
- **P switch IDs from the mission name** (phase P1, 12/10/2026, decided by the author after the failed release of 12/10): up to seedVersion 10 they were `pswitch_<position in the page>`, and the wiki moved a mission («Gather the blue coins around the control tower!», from Forest/`mario_circuit` to Central Grassland/`peach_stadium`), shifting 97 IDs by one and therefore the saved ticks (`completed_p_switches` is by ID). Now `pswitch_` + slug of the name: the 394 names are unique (validate stops duplicate IDs or IDs different from the name). Only the name and not region+name, as first proposed: the moved mission also changed region. The old IDs remain in `manual/legacy_p_switch_ids.yaml` (frozen from seed v10, identical in all published versions, checked with git) and become `seed/p_switch_legacy_ids.json`. **No Room migration** (the schema does not change, Room stays v8): `SeedRepository` remaps the ticks at reseed, before recording the new `seedVersion` (idempotent: if the process dies, it is redone), and `BackupRepository` translates the old IDs at import, because a backup can also land on a fresh install. Backup format unchanged (v3). A mission renamed on the wiki later keeps its ID through `manual/p_switch_renames.yaml` (new name → original name): `manual/legacy_p_switch_ids.yaml` is no longer touched.

## Italian names

- Official names from mariowiki, page by page: for recurring courses the title without disambiguator often leads to a multi-game page with the wrong historical translation, so `wikiPage` in `aliases.yaml` points to the Mario Kart World page. In the "Names in other languages" tables the row **without** a note counts (rows with a note are historical variants, e.g. "Ughetto" for Toad). (25/09/2026)
- Outfits with a male/female variant in Italian (Explorer, Farmer, Sailor, Soft Server, Touring): chosen with `manual/character_genders.yaml`. (25/09/2026)
- **Unofficial manual translations**, declared in the README, `seed/LICENSE` and Settings/Info: food names, including single snacks (`manual/food_names_it.yaml`, no source has them), mirror mode (`manual/mirror_mode_it.yaml`, because mariowiki.it omits the final Special Cup) and places and venue types of the Yoshi's stands (`manual/stand_locations_it.yaml`, 05/10/2026). Each manual file contains the exact EN text, so seedgen stops if the wiki changes it; for the stands it also stops if an entry no longer matches any stand. In the places, courses have the official Italian name, proper names without a known Italian name (Crown Bridge, Pipeline Hotel, Vanilla Lake, Bank Coin Coffer…) stay in English. (26/09–05/10/2026)

## Images and assets

- **Game images downloaded at runtime** (explicit choice of the author, supersedes "no images from the wiki"; since 05/10/2026 also the foods, from the Dash Food page, which is a fixture like the other "core" pages): only URLs in the seed, originals and not thumbnails, validated on the prefix `https://mario.wiki.gallery/images/`; seedgen stops if an image is missing or does not resolve; the default outfit uses the character's image; credits in the README and disclaimer in the app. Earlier the author had asked for icons from mario.fandom.com and from an anonymous Imgur album: rejected (Nintendo artwork or derivatives without a license; a disclaimer does not solve the problem). (25–26/09/2026)
- **Exception to rule 2 wanted by the author**: Home icons (banana, coin, mushroom, star, trophy) and logo cropped from their mockup, "for now", to be replaced with their own icons; each icon is a separate resource. App icon: the author's raster image (globe with the "MKL" initials), confirmed after pointing out to them that it recalls "Mario Kart Log"; artwork at ~64% for the safe zone, `ic_launcher_background` `#139CFC`, no `monochrome` icon. (25–26/09/2026)
- **Lilita One** font (OFL), chosen by me as the closest to the mockup while waiting for the author's. (26/09/2026)
- **Non-breaking spaces in the seed** (R1, 05/10/2026): the `nameIt` of "Rovine del blocco ?" came from the wiki with U+00A0, a glyph Lilita One does not have (checked with fontTools): Android drew it with a fallback font. `normalize_spaces` in seedgen turns them into normal spaces in every seed text (`seedVersion` 10); `test_seed_has_no_non_breaking_spaces` forbids them. Fixed at the source, not in the app code.

## Characters

- The 32 starter drivers are **always** unlocked: `character_unlocks` is ignored for them (old rows included, no migration), tap has no effect, label "Di base". (27/09/2026)
- **The author's colour rule: grey = you are missing it, coloured = you have it** (supersedes the original "dimmed" of SPEC). An unlockable without an already unlocked outfit reopens the popup, the only way to undo a wrong unlock. (27/09/2026)
- Ordering: only those who had something to do and did it go to the bottom (`isDone = hasProgress && isComplete`), whatever ordering is chosen; "Incompleti" hides starter drivers without outfits. "Roster" is the order of `aliases.yaml`, not the game's: the author chose to keep it. (25–27/09/2026)
- The default outfit is a real row in `owned_outfits` (`ensureDefaultOutfitsOwned()` at every start), not a special case in the queries. (25/09/2026)
- Adaptive-column grid (min 104dp, 3 on phone) with vertical images without cropping; in round avatars the top part (the face) is cropped. (26/09/2026)
- **Tappable foods in the character detail** (R1, 05/10/2026): `SkinDao` adds `foodGroupIds` (same sub-query as the names, same order) and `OutfitProgress.foods` matches them; if the counts do not match the list is empty and "cibo sconosciuto" is shown. The food's `clickable` inside the polaroid takes the tap before it, so it does not tick the outfit.

## Collectibles and map

- "Segna tutti" ticks only the missing ones, there is no "untick all". The global P switch counter does not change with the search; sections open by themselves during the search. (25/09/2026)
- Map: markers shaped like the object (blue P circle, pink coin with crown, yellow "?" square), radius that grows with zoom, done points dimmed with a green tick (on the map those still to find must stand out). Opened from a list it shows only that type. `KartChoiceButton` never in `horizontalScroll` (infinite width, `weight` to zero: filters in a 2×2 grid, `MapFiltersTest`). (28/09/2026)
- The author's Home: Characters + Results, P switches + World map, wide Consigliami; Peach Medallions only in the menu. The Results counter = (event, engine class) pairs with a trophy out of events × 4. In the drawer, "Collezionabili" is a header with Peach Medallions, P switches and "?" Panels as sub-items. (28/09/2026)

## Consigliami

- Primary criterion: outfits obtainable with the best **single** character (SPEC §6.3). (25/09/2026)
- **Positions 1, 2, 3 and no "Solo utili"** (05/10/2026, supersedes "tied 1,1,1,4 grouped in one card" and "Solo utili in the ViewModel" of 25/09/2026): on screen the group closed at #1 followed by card #3 looked like a mistake, even with the position on the group. The author chose progressive numbering (the §6.4 tie-breakers decide the order) and to remove the filter: the algorithm always excludes events with gain 0, even with results on, where before they stayed because of the trophy weight.
- The Grand Prix/KO/Both toggle filters the events **before** the algorithm. (25/09/2026)
- **Review of 05/10/2026** (phases C1–C4 in `docs/roadmap.md`): in-game the advice does not add up because the stands of "Course locations" are those of the course's area, not necessarily on the race track, and no source says which ones are met in a race. Author's choices: Consigliami speaks of possibilities ("occhi aperti"); new Cibi section (sub-section of Characters, not collectible, grid with detail) with all the stands of List of Yoshi's locations, roads included, which however are never associated with an event; source mariowiki, not IGN; EN places from the wiki + IT translated by hand, unofficial; "Includi cibi nei dintorni" removed; images of all food variants from the Dash Food page (extends the decision on images); places split by variant only where the source names the specific food (sushi group), not by sizes. Phases with assigned model: Opus for the data (C1), Sonnet for the Cibi section and graphics (C2–C4).
- **Phase C2 done** (05/10/2026): Cibi section as a sub-item of Characters in the drawer (`Destination.Food`, `FoodDetail(foodGroupId)`); no access from the Characters screen until the author asks. Tiles all orange (Characters' colour), never grey. Counter "Ne mancano N" = outfits of the food you do not have; characters without outfits from a food are derived in the ViewModel from `FoodDao.charactersWithOutfits()` (those with at least one non-default outfit). The outfits in the detail cannot be ticked (they are ticked in Characters). After the on-screen test (05/10/2026): the character panels are two per row (a food gives at most one outfit per character, checked on `outfit_food_rules.json`), with first those who still have the outfit to obtain; food images sit in a uniform box because the wiki ones do or do not have a built-in frame. Places are split by variant only if the source names the food (sushi); a stand food that matches no variant has its own section at the end instead of disappearing.
- **Phase C1 done** (05/10/2026): `foods(E)` from the stands of the event's courses (SPEC §6.1), nearby-areas switch removed (it was not a saved preference, only ViewModel state and a route argument of the detail), texts as possibilities ("fino a +N outfit", "Potrebbero esserci (occhi aperti)", warning at the top of the detail) without redoing the graphics. The banner also reminds that the outfit change can be switched off in the vehicle selection (Dash Food page).
- **Consigliami graphics (C3–C4, 05/10/2026):** the author's request after seeing the list: event icons and avatars with a black outline (cropped icons follow the silhouette, not a box) and in the detail the food next to the outfit ("Vespone – Barbecue") as a reminder; the food is a button to the Cibi section. C4 was done by Opus in the same session as C3, at the author's explicit request.

## Results

- A single **trophy** per (event, engine class): bronze < silver < gold < gold ★ < gold ★★ < gold ★★★ (Game Rant; for KOs TheGamer: 1st gold, 2nd silver, 3rd bronze, from 4th none). Only the best is saved. `improvement = 1 - level/6`: a product choice, not game data. Dedicated screen, the only place of recording; Consigliami only reads. (25/09/2026)
- **No carry-over between engine classes** (Kotaku claims it, the author is not sure). The v2→v3 migration converts: 1st → gold + stars, 2nd silver, 3rd bronze, the rest no row. (25/09/2026)
- **Results with the `Kart*`** (R1): no `ListItem`/`AlertDialog`/`RadioButton`; same scheme as Consigliami (orange GP, green KO). The trophy choice is a `KartPopup`; "Nessun trofeo" deletes. No logic change.

## Backup and Settings

- Import **replaces** all user state (like the restore of ThePatientGamerHelper) and reports unknown IDs instead of discarding them; default outfits come back by themselves. Data attribution in the same Settings/Info screen. (25/09/2026)
- Language and theme selectors (author's request): AppCompat and DataStore as in ThePatientGamerHelper. Plus `AppLocale`/`relocalizing()`, because here game names are localized in the ViewModels, which survive the activity's recreation. (26/09/2026)
- **In-app updates** (author's request, phase A1): check of this repository's GitHub Releases only at startup, frequency Mai / A ogni avvio / Ogni giorno / Ogni settimana (default every week), "Non ora" just closes, the dialog shows the release body (the CHANGELOG bold titles) and the link to the full changelog; installation with `PackageInstaller` and system confirmation. Code copied from ThePatientGamerHelper (pilot for all six apps), not a shared library. Version, "fatto con ❤ da marcogn" and manual check in the Info section. (11/10/2026)
- **INTERNET also for updates** (phase A1): the "offline except images" rule widens to the release check and download from GitHub only; it is switched off with "Mai". Rule 3 of `CLAUDE.md`, `SPEC.md` §0 point 3 and the manifest comment updated in A1. (11/10/2026)
- **A1: choices made by copying from the pilot (ThePatientGamerHelper `95f0b97`, release 1.1.2), where the plan diverged** (12/10/2026, confirmed by the author): **Info remains the section at the bottom of Settings** (no About screen or new route); **`UpdatePreferences` on SharedPreferences** like the pilot, not in the DataStore of `ThemePreferences` (two values, synchronous read, already proven on the phone); credits line of pilot 1.1.1 («Fatto con il ❤️ da Marcogn» / «Made with ❤️ from Marcogn»); **no version code in Info** (removed from the pilot in 1.1.2). Taken from the pilot beyond the plan: `UpdateInstallReceiver` in the manifest, `BuildConfig.UPDATE_GITHUB_OWNER/REPO` (with `buildFeatures.buildConfig = true`), cleanup of leftover APKs at every start, `Checking`/`Installing` states, «Pronto per l'installazione» step with an explicit **Installa** (after the system confirmation is refused it returns there, an automatic install would loop). The rest (signing, HTTP, concurrency) is in the pilot's decisions 9.1/9.2, `docs/implementation-decisions.md`.
- **A1: in the `KartPopup`s the X and the tap outside do what the give-up button does** (Annulla during the download, Non ora once the download is finished), because `KartPopup` is not non-dismissible; the pilot blocked them with `AlertDialog`. In «Pronto per l'installazione» the tap outside therefore deletes the verified APK: it costs a new download. The list of titles in the dialog scrolls in 200 dp so the buttons always stay visible. Test fixture: real `releases/latest` response of KartLog v1.2.0 (12/10/2026), without the author's URLs.

## Navigation and UI

- Home from the drawer: `popUpTo<Home>{inclusive=true}` + `launchSingleTop`, without `saveState`/`restoreState` (with the same target for `navigate` and `popUpTo` Navigation Compose did not restore Home reliably). (25/09/2026)
- Predictive back gesture: Navigation 2.10 uses separate transitions (`predictivePop*`, default `scaleOut(0.7f)`) and ignores `popEnter/popExit` during the gesture: the same as the pop are passed to `NavHost`. (04/10/2026)
- `OutlinedTitle` removes the outline text from the semantics (TalkBack read every title twice). (27/09/2026)
- Theme: custom Material 3 palette, dynamic colour off (the "game" look does not depend on the wallpaper). (25/09/2026)

## Toolchain, build and CI

- **Alignment with ThePatientGamerHelper** (phase 1): same Gradle structure, signing from environment variables (4 variables, unsigned release if absent), build types, `release.yml` that bumps only after the release, `.gitignore` (plus generated seed assets and seedgen venv), `SECURITY.md`, package per feature, Hilt, Room, type-safe navigation with drawer, IT/EN i18n, theme from DataStore. Divergences: README/CHANGELOG in Italian (project rule until phases I1–I2, see "Repository language"; same bullet convention, which `release.yml` reads), custom palette, Dependabot added with the kit (09/10/2026, see below). `versionCode = 1`, `versionName = "0.1.0"` as the scaffold's starting point.
- **Dependency update of 04/10/2026**, like PdfToolkit: only stable versions, third-party libraries in the same major. Gradle 9.8.0 (with `distributionSha256Sum`), AGP 9.4.1 with built-in Kotlin (no `kotlin-android` plugin, `kotlin { compilerOptions { } }`), Kotlin 2.4.20, KSP 2.3.12, Hilt 2.60.1, Compose BOM 2026.09.00, Navigation 2.10.2, Room 2.8.5, Coil 3.6.3, `compileSdk` 37. **`targetSdk` stays 36** until the app is tried on Android 17 (it changes runtime behaviour; lint reports it as a warning). In the code: `project.exec` (removed in Gradle 9) replaced by `ProcessBuilder` in `generateSeed`; the seed assets folder passed as a `File` (AGP 9 rejects `Provider`s in sourceSets). Remaining warnings: `createComposeRule` deprecated in Compose tests, two superfluous `!!`.
- **The author's Android kit** (09/10/2026, version `dbb33a5`, supersedes "PdfToolkit's generic workflows"): `.github/workflows/` contains short callers of the reusable workflows of [claude-skill-android-kit](https://github.com/Marcogn/claude-skill-android-kit) (`docs/ci.md`, in English); `.claude/` (skills, reviewer agent, SDK hook), `docs/claude.md`, `REVIEW.md`, PR and issue templates, `dependabot.yml` (Gradle weekly, Actions monthly: the "manual updates" choice is dropped). Adaptations: `FORBIDDEN_PERMISSIONS` empty (INTERNET is needed); PR CI stays offline on the seed: `release-build-args: -PofflineSeed`, only on the release build as before; *Build APK* and *Release* do the online check. JaCoCo coverage with `-Pcoverage` (`enableUnitTestCoverage` in the debug build type). No APK uploaded by CI. R8 off (`isMinifyEnabled = false`): turning it on is a separate choice.
- **Kit updated to `425e232`** (09/10/2026): the `architecture-reviewer` agent always runs on Opus (`model: opus`), whatever the session's model. Previously, `85b2e8a`: added the `new-plan` skill (plans new work as a draft PR, without writing code), `next-phase` includes the issues the plan assigns to the phase, `docs/claude.md` with the two flows (new work / planned work). No local changes to reconcile; `android-ci.yml` stays with KartLog's values (`release-build-args: -PofflineSeed`).
- **Repository language** (17/10/2026, issue #36, phases I1–I2): documentation, README, CHANGELOG, commits, PRs and issues in English; the app stays IT (default) + EN. Author's choices: (1) CHANGELOG in English only, even though the update dialog shows its titles to those who use the app in Italian: a bilingual dialog would require changing `release.yml` and the notes parser for little gain; (2) **code comments in Italian** as they are, to avoid a diff over 120+ files with no functional value; (3) the **CHANGELOG history** translated too, for an all-English file (the release notes already published on GitHub stay in Italian); (4) `docs/decisioni.md` becomes `docs/decisions.md`.
- **Release build**: seedgen runs before the assets; changed data stops the build until accepted with `-PacceptSeedChanges`. Debug uses no network or Python. (25/09/2026)
- **Versioned Room schemas** in `app/schemas/` (Room's recommendation): KSP writes them as an undeclared side effect, and with the build cache `MigrationTest` failed intermittently on clean checkouts; declaring them as task outputs would delete the old schemas. Also `mergeDebugAssets` depends on `kspDebugKotlin`. Migrations always written and tested, never `fallbackToDestructiveMigration()`. (25/09/2026)
- **Tests**: Robolectric pinned to `sdk=34` (the newer shadows ask for JDK 21); without an emulator, UI flows are covered with Robolectric/JVM tests, and the on-screen check is done by the author. (25/09/2026)
- **CHANGELOG** compacted towards 1.0 into one "[0.1.x] - beta" entry (the v0.1.x releases remain, but their links to the sections no longer find the anchor); manual workflow `cleanup-runs.yml` to delete the Actions history while keeping the last run per workflow. (27/09/2026)
- `SeedFile<T>` has no `source` field (sometimes a string, sometimes an array); whoever needs it reads it with a dedicated DTO (`SourceOnlyDto`, `SeedAssetLoader.readSourceUrl()`). (25/09/2026)
- Agents per phase: Opus only where a design error costs dearly, Sonnet for the rest; every session checks the model at the start (protocol in `CLAUDE.md`). (05/10/2026)
- **Kit updated** (14/10/2026, from `425e232` to `5fb47c3`): new `self-review` and `review-gate.sh` hook (mandatory review before the PR), `branch-name.sh`, `deps-triage` skill, Release with `bump` choice and Actions history cleanup (`actions: write`), Dependabot with cooldown. Copied unchanged, no new adaptation; the project's values (`app-module`, Java 17, `release-build-args: -PofflineSeed` in CI) stay as they were.
