# KartLog — project memory for the agent

Offline Android app to track the Mario Kart World collectibles (outfits, Peach Medallions, P Switches, "?" panels) and recommend which Grand Prix or Knockout Tour to race, and with whom, to unlock more outfits.
This file holds rules, protocol, commands, conventions and status. It does not repeat the other documents:

| `tools/seedgen/README.md` | Usage of the script that generates `seed/` |

## Non-negotiable rules
1. **No invented game data.** Everything comes from `seed/`, generated by `tools/seedgen`. Never edit `seed/` by hand, never write game data in code or tests (Kotlin tests use a fake seed marked `FAKE_FOR_TESTS`).
2. **No Nintendo assets** in the repository or the APK: no renders, logos, fonts, screenshots. Game images are only URLs in the seed, downloaded at runtime. The author's only intended exception: the Home icons and the banner of their mockup (`res/drawable-nodpi/home_*`, `kart_*`). No "Mario", "Mario Kart" or "Nintendo" in the app name or package.
3. **App offline except images and updates**: INTERNET is for downloading images (Super Mario Wiki CDN and the mkworld-checklist map from GitHub) and for checking/downloading this repository's releases (`api.github.com`, SPEC §4.1; "Mai" switches it off). Game data is downloaded only at release build (seedgen).
4. **The counts in `tools/seedgen/expected_counts.yaml` are never relaxed** to make a build or test pass. They change only if the game changes, in a dedicated commit citing the source.
5. If a requirement is ambiguous or data is missing, **stop and ask**. Do not pick the "plausible" value.
6. At the end of a session the project compiles and the tests pass. Room migrations always written and tested, never `fallbackToDestructiveMigration()` (real users).

## Session protocol
When the author writes "vai avanti con la prossima fase" (or similar):
0. **Model check, first of all.** Take the next phase from **Current status** and its model from the table in `docs/roadmap.md`. Check which model you are running on (system prompt; in a claude.ai cloud session the `get_session` tool says it). If it is not the assigned one, or you don't know, **stop** and answer in one line: phase, required model, how to switch (`/model opus`, `/model sonnet` or a new session). Do not read SPEC or code first. Go on anyway only if the author explicitly says so.
1. Read the phase section in `docs/roadmap.md` (goal, prerequisites, scope, "Fatto quando") and the parts of `SPEC.md` and `docs/decisions.md` it touches.
2. Check the prerequisites **before** writing code. If one is missing, stop and ask.
3. Do **only** that phase. What belongs to a later phase is noted in Current status, not implemented.
4. Close with the phase's "Fatto quando" points and the common ones at the bottom of `docs/roadmap.md`. An Opus phase writes a **handoff** (max 15 lines) in Current status for the next one; every phase ends by listing the **on-screen checks** (there is no emulator here).
5. Do not start the next phase in the same session unless the author asks.
6. **Review before every PR**: `self-review`, enforced by `.claude/hooks/review-gate.sh` (stops the session end once and blocks the PR until the diff is reviewed). Work for later phases → Current status; bugs and out-of-scope ideas → GitHub issues (`docs/claude.md`).
7. **Names** (`docs/claude.md`): session title with `set_session_title` (`KartLog <what>`); branches you create `<type>/<what-and-where>`.

## Commands
```bash
./gradlew assembleDebug       # debug APK: no network, no Python
./gradlew testDebugUnitTest   # JVM tests (Robolectric sdk=34)
./gradlew lint                # Android Lint
./gradlew testDebugUnitTest createDebugUnitTestCoverageReport -Pcoverage   # JaCoCo coverage, on request only

cd tools/seedgen && python -m pytest                    # script tests, no network
python -m seedgen validate --seed ../../seed            # validate seed/
python -m seedgen release --seed ../../seed --work ../../app/build/seedgen/candidate   # what Gradle does in release

./gradlew generateSeed -PofflineSeed          # validate seed/ without network (like CI)
./gradlew assembleRelease -PacceptSeedChanges # accept changed data and update the CHANGELOG automatically
```
Release build flags: `-PacceptSeedChanges`, `-PofflineSeed`, `-PpythonExec=<path>` (SPEC §5.4).
**Cloud environment:** the Android SDK is installed by the hook `.claude/hooks/android-sdk.sh` (`docs/claude.md`); Gradle with `LC_ALL=C.UTF-8` (accented test names); Maven Central may answer 429, just retry; seedgen works with the system `python3` (sometimes Gradle's venv can't be created because `ensurepip` is missing); in `tools/seedgen` run pytest with `--ignore-glob='*_live.py'` when there is no network (the live tests hang).

## Conventions
- Documentation, CHANGELOG, commits, PRs and issues in English; identifiers in English; code comments may stay Italian. UI IT (`values/`, default) + EN (`values-en/`). CHANGELOG: every visible change under `## [Unreleased]` as `- **Summary.** detail` (`release.yml` reads the bold text).
- Stack and structure follow **ThePatientGamerHelper** (the author puts it in the context, don't look it up online): Kotlin, Compose, Material 3, Room, Hilt, MVVM with `StateFlow`. Package `com.marcogn.kartlog`: `ui/<feature>/` (`home`, `skin` = Personaggi, `food` = Cibi, `medallions`, `pswitches`, `panels`, `map`, `consigliami`, `results`, `settings`, `update`, plus `theme`, `navigation`, `common`), `data/`, `domain/`, `di/`.
- Game data IDs: stable seedgen slugs (`mario__touring`, `cup_mushroom`, P Switches `pswitch_<name>` since seedVersion 11), never autoincrement nor position in the page.
- **Data:** the Room entities (SPEC §3) are the source of truth; `SeedRepository` reseeds by comparing `seedVersion` without losing user state (it only remaps the old P Switch IDs, phase P1). At runtime only the `assets/seed/*.json` assets copied by `copySeedAssets`, never `seed/`. One DAO per screen with direct SQL queries (JOIN, GROUP_CONCAT) and a single `Flow`. Versioned Room schemas in `app/schemas/`.
- **Navigation:** `Destination` sealed interface with `@Serializable` routes. `ModalNavigationDrawer` (`ui/navigation/KartDrawer.kt`), entries with `popUpTo(Home){saveState}` + `launchSingleTop` + `restoreState`, except Home (`popUpTo<Home>{inclusive}` + `launchSingleTop`). 300 ms slide+fade transitions on `NavHost`, `predictivePop*` too. `lifecycleIsResumed()` guard on every `navigate()`/`popBackStack()`.
- **"Game-style" graphics** (the author's mockup), to use in every new screen: `ui/common/KartChrome.kt` (`KartTopBar` with banner, `KartPanel`, `KartBadge`, `KartCounterPill`, `OutlinedTitle`, `KartTitle`), `Modifier.kartSky(dark)` behind every `Scaffold` with `containerColor = Color.Transparent`, choices with `KartChoiceButton`/`KartDropdown` (never `FilterChip`, never `KartChoiceButton` in `horizontalScroll`), `KartTabs`, popups `KartPopup`/`KartPopupText`/`KartSwitchRow`/`KartInfoButton`, Lilita One font (`KartFont`), `isKartDarkTheme()`. Polaroid in `ui/skin/Polaroid.kt`, label colour extracted from the image (`rememberImageAccentColor`). Never `BoxWithConstraints`/SubcomposeLayout where the parent asks for intrinsic measurements (crash, `KartDropdownTest`). Colours: **grey = you are missing it, coloured = you have it**.
- **Images:** `imageUrl` from the seed, loaded with Coil (`CharacterPortrait`, `CharacterAvatar`, `EventIcon` in `ui/common/CharacterAvatar.kt`), cached at startup by `WikiImagePrefetcher`; placeholder with initials only until they are loaded.
- **Characters:** 50 drivers, the 32 `starter` always unlocked (`CASE WHEN c.starter THEN 1 ELSE COALESCE(cu.unlocked, 0) END` in `SkinDao` and `ConsigliamiDao`); tap behaviour in `cardBehavior()` (`CharacterCardBehavior.kt`, tested on all drivers of the real seed). The default outfit is always in `owned_outfits`.
- **Consigliami:** pure algorithm in `domain/consigliami/` (`ConsigliamiUseCase`, no Android dependency), tested with synthetic data; the DAO exposes only raw `Flow`s, the ViewModel recombines them. Never domain logic in the ViewModel or the DAO. Results: only from the `ui/results/` screen, one `TrophyRank` per (event, engine class).
- **Localization:** `localizedName(name, nameIt)` with `AppLocale`; every ViewModel that localizes passes its Flow through `relocalizing()`. `MainActivity : AppCompatActivity` (`setApplicationLocales()`).
- **Backup** (`data/backup/`): import replaces all user state and reports unknown IDs.
