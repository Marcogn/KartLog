# KartLog — memoria di progetto per l'agente

App Android offline per tracciare i collectibles di Mario Kart World (outfit, Peach Medallions, P Switch) e consigliare quale Gran Premio o Knockout Tour correre, e con chi, per sbloccare più outfit.
La specifica completa è `SPEC.md`. Questo file **non la ripete**: contiene regole operative, comandi, stato e decisioni.

## Regole non negoziabili
1. **Nessun dato di gioco inventato.** Tutto arriva da `seed/`, generato da `tools/seedgen`. Mai modificare `seed/` a mano, mai scrivere dati di gioco nel codice o nei test (per i test Kotlin si usa un seed fittizio marcato `FAKE_FOR_TESTS`).
2. **Nessun asset Nintendo** nel repository né nell'APK: niente render, loghi, font, screenshot. Le immagini di gioco sono solo URL nel seed, scaricate a runtime (vedi Decisioni prese, 2026-09-26). Unica eccezione voluta dall'autore: le icone della Home e il banner del suo mockup (`res/drawable-nodpi/home_*`, `kart_*`). Niente "Mario", "Mario Kart" o "Nintendo" nel nome dell'app, nel package o nell'icona.
3. **App offline tranne le immagini**: INTERNET serve solo al download delle immagini (CDN di Super Mario Wiki, e la mappa di mkworld-checklist da GitHub); tutto il resto funziona senza rete. I dati di gioco si scaricano solo al build release (seedgen).
4. **I conteggi in `tools/seedgen/expected_counts.yaml` non si rilassano mai** per far passare build o test. Si cambiano solo se il gioco cambia, in un commit dedicato che cita la fonte.
5. Se un requisito è ambiguo o manca un dato, **fermati e chiedi**. Non scegliere il valore "plausibile".
6. A fine sessione il progetto compila e i test passano.

## Comandi
```bash
# App
./gradlew assembleDebug       # APK debug: nessuna rete, nessun Python
./gradlew testDebugUnitTest   # test unitari JVM
./gradlew lint                # Android Lint

# Dati di gioco
cd tools/seedgen && python -m pytest                    # test dello script, senza rete
python -m seedgen validate --seed ../../seed            # valida seed/
python -m seedgen release --seed ../../seed --work ../../app/build/seedgen/candidate   # quello che fa Gradle in release

# Task Gradle (SPEC §5.4)
./gradlew generateSeed -PofflineSeed          # valida seed/ senza rete, come farebbe la CI senza accesso a mariowiki.com
./gradlew assembleRelease -PacceptSeedChanges # accetta i dati cambiati e aggiorna da solo il CHANGELOG
```
Flag della build release: `-PacceptSeedChanges`, `-PofflineSeed`, `-PpythonExec=<path>` (SPEC §5.4).

## Convenzioni
- Lingua di UI e documentazione: italiano. Identificatori nel codice: inglese.
- ID dei dati di gioco: slug stabili generati da seedgen (`mario__touring`, `cup_mushroom`), mai autoincrement.
- Package `com.marcogn.kartlog`, struttura per feature sotto `ui/<feature>/` (`home`, `skin`, `medallions`, `pswitches`, `consigliami`, `settings`, più `theme`, `navigation`, `common`), stesso schema di ThePatientGamerHelper. `data/` e `domain/` si creano dalla fase 3 in poi, quando arrivano le entità Room.
- Navigazione: `Destination` è una `sealed interface` con rotte `@Serializable` (Navigation Compose type-safe), non un grafo con stringhe. Il drawer è `ModalNavigationDrawer` con `drawerState` sollevato a livello di `KartLogNavGraph`; ogni voce del drawer naviga con `popUpTo(Destination.Home){saveState=true}` + `launchSingleTop` + `restoreState`, **tranne Home stesso** (`popUpTo<Destination.Home>{inclusive=true}` + `launchSingleTop`, senza `restoreState`: vedi Decisioni prese). Transizioni 300ms slide+fade su `NavHost` e guardia `lifecycleIsResumed()` su ogni `navigate()`/`popBackStack()`, allineate a ThePatientGamerHelper.
- Tema: palette Material 3 custom in `ui/theme/Color.kt`/`Theme.kt` (arancio/verde acqua/magenta), colore dinamico **disattivato** deliberatamente — la palette "da gioco" non deve dipendere dal wallpaper dell'utente. Dettaglio completo dell'allineamento a ThePatientGamerHelper in `docs/ALIGNMENT.md`.
- Dati: `data/local/entity` (entità Room, SPEC §3) è la fonte di verità; `data/seed` ha i DTO kotlinx.serialization sui JSON reali e `SeedRepository`, che fa il reseed confrontando `seedVersion` senza mai toccare le tabelle di stato utente. Mai leggere `seed/` direttamente a runtime: solo l'asset `assets/seed/*.json` copiato da `copySeedAssets` (debug e release).
- Immagini: `imageUrl` su `characters`/`outfits`/`events`, estratto da `tools/seedgen/seedgen/images.py` dalla pagina "Mario Kart World" (sempre dal vivo, come i nomi in italiano). L'app le carica con Coil (`ui/common/CharacterAvatar.kt`: `CharacterPortrait` rettangolare, `CharacterAvatar` tondo, `EventIcon`) e `WikiImagePrefetcher` le mette in cache all'avvio. Il segnaposto con le iniziali si disegna solo finché l'immagine non è caricata (offline senza cache resta quello): se restasse sotto, si vedrebbe attraverso le card attenuate. Mai file immagine nel repository o negli asset.
- Personaggi (package `ui/skin`, nome storico della schermata): tutti i 50 piloti; solo i 24 con outfit hanno il dettaglio. I 32 piloti di base (`starter`) sono **sempre** sbloccati, niente lucchetto né interruttore; per i 18 da sbloccare vale la scelta dell'utente (popup col criterio), altrimenti bloccati: `CASE WHEN c.starter THEN 1 ELSE COALESCE(cu.unlocked, 0) END`, in `SkinDao` e `ConsigliamiDao`. Colori: **grigio = ti manca, colorato = ce l'hai** (pilota grigio solo se bloccato; nel dettaglio outfit grigio se non ottenuto). Tap: bloccato → popup; sbloccato con outfit → dettaglio; sbloccabile senza outfit → popup (per poterlo ribloccare); di base senza outfit → niente. Tutto in `ui/skin/CharacterCardBehavior.kt` (`cardBehavior()`, funzione pura), verificato su tutti i 50 piloti del seed reale da `CharacterCardBehaviorTest`; "da sbloccare" = `!starter`, stessa fonte della query, mai la presenza del criterio. `SkinDao` incrocia dati seed e stato utente con query SQL dirette (JOIN + GROUP_CONCAT), non con più chiamate separate — un solo `Flow` per schermata. L'outfit di default è sempre in `owned_outfits` (`ensureDefaultOutfitsOwned()`, chiamata da `SeedRepository` a ogni avvio): il contatore "ottenuti/totali" non ha bisogno di trattarlo come caso speciale in UI, solo di non mostrargli la checkbox.
- Monete Peach/Pulsanti P: stesso pattern di `SkinDao` (`MedallionsDao`/`PSwitchesDao`, una query con JOIN per schermata). Monete Peach = le 200 monete una per una (dal 28/09/2026, niente più biomi); Pulsanti P usa ancora `ui/common/RegionSection.kt`. Pannelli "?" (`ui/panels/`, `QuestionPanelsDao`) = come Monete Peach: le due liste condividono `ui/common/MapPointList.kt` (`MapPointListScreen`). Tutte e tre hanno il pulsantone `KartMapButton` (rosso, icona bianca) e l'icona "Mostra sulla mappa" per riga; nel drawer stanno sotto l'intestazione "Collezionabili" (`SubItem`, più piccole e rientrate).
- Mappa (`ui/map/`): `MapDao.allPoints()` = una UNION di monete, Pulsanti P e pannelli "?" con lo stato; `Destination.CollectibleMap(type, focusId)` (tipo da mostrare da solo e punto da centrare; senza argomenti = dal drawer, con il menu). Zoom/trascinamento/tocco in `MapViewport` (logica pura, `MapViewportTest`), immagine con Coil a `Size.ORIGINAL` trasformata con `graphicsLayer`, marker disegnati sopra su `Canvas` a dimensione costante. Filtri (`filterPoints`) per tipo e "Fatti". `map.json` letto dagli asset (`readMapImage()`), nessuna tabella. Avvisi una tantum scritti da una migrazione: tabella `pending_notices`.
- Consigliami: l'algoritmo (SPEC §6) vive in `domain/consigliami/` come Kotlin puro (`ConsigliamiUseCase`, nessuna dipendenza Android/Room), testato con dati sintetici in `ConsigliamiUseCaseTest`. `ConsigliamiDao` espone solo `Flow` sulle tabelle grezze; `ConsigliamiViewModel` fa da ponte, ricombinando i `Flow` e rieseguendo l'algoritmo a ogni cambiamento — mai logica di dominio nel ViewModel o nel DAO.
- Risultati: schermata dedicata `ui/results/` (pulsante largo in Home + drawer), **unico** punto di registrazione. Tabella `best_results` con un solo `TrophyRank` per (evento, cilindrata), upsert. Nessun riporto tra cilindrate: un trofeo vale solo dove è registrato. Consigliami legge i risultati e basta.
- Backup: `data/backup/` (non `domain/`) perché è solo mappatura dati↔JSON, nessun algoritmo puro da isolare. Un import **sostituisce** tutto lo stato utente (mai un merge) e valida ogni ID contro il seed corrente prima di scrivere, riportando gli sconosciuti invece di scartarli.
- Nomi in italiano: `nameIt` su `characters`/`outfits`/`courses` (mariowiki.com, `seedgen/i18n.py`), su piloti senza outfit/`regions`/`events` (mariowiki.it, `seedgen/it_wiki.py`, solo dove .com non basta) e su `food_groups` (traduzione manuale NON ufficiale). Missioni dei pulsanti P: solo inglese. `localizedName(name, nameIt)` usa `AppLocale` (aggiornato da `MainActivity` con la lingua della configurazione, che segue il selettore in Impostazioni anche sotto Android 13); ogni ViewModel che localizza fa passare il suo Flow da `relocalizing()`, altrimenti dopo un cambio di lingua terrebbe i nomi vecchi.
- Grafica "da gioco" (mockup dell'autore): `ui/common/KartChrome.kt` con `KartTopBar` (banner in alto su ogni schermata, stessi slot di `TopAppBar`; logo in Home), `KartPanel`/`KartBadge`/`KartCounterPill`/`OutlinedTitle` per le tessere, `KartFooter` solo in Home (sfuma con maschera alfa), `Modifier.kartSky(dark)` = cielo con nuvole disegnato dietro ogni `Scaffold` (`containerColor = Color.Transparent`), drawer in `ui/navigation/KartDrawer.kt`, colori condivisi in `KartTiles`. Card dei personaggi a polaroid: colore del cartellino estratto dall'immagine del wiki con Palette (`rememberImageAccentColor`), mai scritto a mano per personaggio; polaroid condivisa in `ui/skin/Polaroid.kt` (dettaglio outfit: cornice del colore del personaggio, default come in Personaggi). Scelte con `KartChoiceButton`/`KartDropdown` (pulsantoni rossi, mai `FilterChip`), titoli del banner con `KartTitle`. Mai `BoxWithConstraints`/SubcomposeLayout dove il genitore chiede misure intrinseche (`DropdownMenu`, righe `IntrinsicSize`): crasha (bug reale su "Ordina per", test `KartDropdownTest`); per questo `OutlinedTitle` con `minFontSize` misura e disegna il testo in un `Layout`. Risultati a schede per cilindrata (`KartTabs`). Popup con `KartPopup` (rosso a quadri, X in alto a destra), `KartPopupText`, `KartSwitchRow`, `KartInfoButton`. Font Lilita One (OFL, `res/font`, licenza in `assets/licenses`) su titoli e intestazioni (`KartFont`). `isKartDarkTheme()` = tema scuro effettivo (anche scelto in Impostazioni).
- Impostazioni: tema (`ThemeMode` su DataStore, `ThemeViewModel`) e lingua (`AppLanguage`, `setApplicationLocales()`, `autoStoreLocales`), come ThePatientGamerHelper; `MainActivity : AppCompatActivity`.
